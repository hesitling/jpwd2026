## 为什么

当前分类树（VaultPanel 左侧面板）仅用于展示和筛选，用户无法直接在树上添加或删除分类。已有的 `CategoryManagementDialog` 虽然实现了完整的 CRUD 功能，但从未被任何 UI 入口调用。用户管理分类必须离开当前工作流，打开一个独立的对话框——这增加了操作成本，也让分类管理变得不直观。

我们需要让分类管理成为密码浏览体验的自然延伸：在树上直接添加、删除、双击重命名。

## 变更内容

1. **分类树底部新增按钮栏**：「添加」和「删除」按钮，提供快速的分类增删入口。
2. **分类树支持内联编辑**：双击分类节点可直接重命名，Enter 保存，Escape 取消。
3. **分类节点存储 Category 对象**：替代当前的纯字符串，使节点能直接携带 ID 和颜色信息，避免额外的数据库查询。
4. **分类节点显示颜色圆点**：在分类名称左侧渲染颜色标记，增强视觉辨识度。
5. **优化 filterByCategory**：参数从分类名称（String）改为分类 ID（Integer），消除按名称反查 ID 的冗余查询。

## 功能 (Capabilities)

### 新增功能

- `category-tree-inline-edit`: 分类树内联编辑功能——双击节点进入编辑模式，验证名称后保存到数据库，支持空值检查和重名检查。
- `category-tree-actions`: 分类树快捷操作——底部按钮栏提供添加和删除入口，删除前检查关联的密码条目并提示用户。

### 修改功能

- `category-management`: 扩展分类管理的 UI 入口。现有规范描述了独立的管理对话框，本次变更将添加/删除/编辑能力下沉到分类树面板。需求层面新增：树节点内联编辑、树面板快捷按钮。

## 影响

- **主要改动文件**：`VaultPanel.java`（分类树构建、按钮栏、编辑器、渲染器、筛选逻辑）
- **无需改动**：`CategoryService.java`、`CategoryRepository.java`（已有完整 API）
- **保留不动**：`CategoryManagementDialog.java`（未来可作为菜单入口的备选方案）
- **无破坏性变更**：不修改任何现有 API 或数据模型，仅扩展 UI 层

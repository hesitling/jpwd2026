## 上下文

为Java课程创建一个密码管理器应用程序。当前状态是全新的项目，只有基本的Maven项目结构。需要从零开始构建一个功能完整的密码管理器，包含安全存储、用户界面、数据库操作等核心功能。

约束条件：
- Java 21
- Maven构建工具
- 必须使用Swing作为GUI框架
- 必须使用SQLite作为数据库
- 必须实现安全的密码存储（Argon2id + AES-GCM-256）
- 课程作业时间限制

利益相关者：
- 学生（开发者）
- 课程教师（评估者）
- 最终用户（使用密码管理器的人）

## 目标 / 非目标

**目标：**
1. 实现安全的密码存储，使用Argon2id哈希主密码，AES-GCM-256加密存储的密码
2. 创建直观易用的Swing图形界面
3. 实现可配置的密码生成器，支持长度和字符类型配置
4. 实现超时锁定功能，保护用户隐私
5. 支持CSV格式的导入导出功能
6. 实现分类管理，方便用户组织密码条目
7. 提供搜索功能，快速查找密码条目
8. 确保应用程序的稳定性和错误处理

**非目标：**
1. 不实现多用户支持（单用户应用）
2. 不实现云同步功能
3. 不实现浏览器扩展或自动填充
4. 不实现移动端应用
5. 不实现复杂的密码共享功能
6. 不实现密码强度策略强制（仅提供建议）

## 决策

### 1. GUI框架：Swing vs JavaFX
**决策**：选择Swing
**理由**：
- Swing是Java标准库的一部分，无需额外依赖
- 学习曲线相对平缓，文档丰富
- IDEA支持良好，便于调试
- 对于课程项目，Swing功能足够
**替代方案**：JavaFX更现代，但需要额外依赖，学习成本较高

### 2. 数据库：SQLite vs H2 vs 文件存储
**决策**：选择SQLite
**理由**：
- 轻量级，无需安装服务器
- 支持SQL标准，功能完整
- 单文件存储，便于备份和迁移
- 性能满足需求
**替代方案**：H2也是嵌入式数据库，但SQLite更轻量；文件存储（JSON/XML）功能有限

### 3. 加密库：password4j vs Bouncy Castle vs 内置JCE
**决策**：混合使用password4j和内置JCE
**理由**：
- password4j专门用于密码哈希，支持Argon2id，API简洁
- 内置JCE支持AES-GCM-256，无需额外依赖
- 减少外部依赖数量
**替代方案**：Bouncy Castle功能全面，但体积较大；纯内置JCE需要自己实现Argon2id

### 4. 架构模式：MVC vs 分层架构
**决策**：选择分层架构
**理由**：
- 职责分离清晰，便于维护和测试
- 适合中等规模的应用程序
- 各层可以独立开发和测试
**替代方案**：MVC更适用于Web应用，对于桌面应用分层架构更合适

### 5. 配置管理：Properties文件 vs JSON vs 数据库
**决策**：选择Properties文件
**理由**：
- Java原生支持，无需额外依赖
- 格式简单，易于编辑
- 适合存储简单的键值对配置
**替代方案**：JSON更结构化，但需要解析库；数据库存储过于复杂

### 6. 导入导出格式：CSV vs JSON vs XML
**决策**：选择CSV格式
**理由**：
- 简单通用，用户熟悉
- 易于用Excel等工具编辑
- 明文格式便于调试
**替代方案**：JSON更结构化，但用户不熟悉；XML过于复杂

### 7. 密码生成策略：可配置 vs 固定策略
**决策**：完全可配置
**理由**：
- 用户有不同的密码策略需求
- 可以适应不同的网站要求
- 提高用户体验
**替代方案**：固定策略简单但不灵活

## 风险 / 权衡

### 风险1：加密实现的安全性
**风险**：自己实现的AES-GCM-256可能存在安全漏洞
**缓解措施**：
- 使用Java标准库的加密实现
- 遵循最佳实践（随机IV、正确的密钥长度）
- 进行安全测试

### 风险2：数据库安全性
**风险**：SQLite数据库文件可能被直接访问
**缓解措施**：
- 所有敏感数据都经过加密存储
- 数据库文件权限设置
- 考虑数据库文件加密（可选）

### 风险3：剪贴板泄露
**风险**：密码在剪贴板中可能被其他程序读取
**缓解措施**：
- 实现自动清除功能
- 用户可配置清除时间
- 提供安全提示

### 风险4：内存中的敏感数据
**风险**：密码在内存中可能被转储
**缓解措施**：
- 使用char[]而非String存储密码
- 及时清除敏感数据
- 避免在日志中记录敏感信息

### 风险5：用户体验
**风险**：安全措施可能影响用户体验
**缓解措施**：
- 提供合理的默认配置
- 允许用户自定义超时时间
- 提供清晰的用户提示

### 权衡：安全性 vs 易用性
**权衡**：更高的安全性通常意味着更复杂的操作
**平衡点**：
- 提供合理的默认安全设置
- 允许用户调整安全级别
- 在关键操作上强制安全措施

### 权衡：功能完整性 vs 开发时间
**权衡**：更多功能需要更多开发时间
**平衡点**：
- 优先实现核心功能
- 预留扩展接口
- 分阶段开发

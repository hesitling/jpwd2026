# 密码管理器架构文档

## 1. 系统概述

密码管理器是一个桌面应用程序，用于安全地存储和管理用户的密码。系统采用分层架构，确保安全性、可维护性和可扩展性。

### 1.1 设计目标

- **安全性**：使用强加密算法保护敏感数据
- **可用性**：提供直观的图形用户界面
- **可维护性**：清晰的代码结构和模块化设计
- **可扩展性**：易于添加新功能和支持新的加密算法

### 1.2 约束条件

- Java 21
- 桌面应用程序（非Web应用）
- 单用户模式
- 本地存储（无云同步）

### 3.1 层次职责

#### 表示层 (Presentation)
- 负责用户界面展示和用户交互
- 处理用户输入和事件
- 调用业务逻辑层完成业务操作
- 不包含业务逻辑

#### 业务逻辑层 (Business)
- 实现核心业务逻辑
- 协调多个数据访问操作
- 处理业务规则和验证
- 管理事务和会话

#### 数据访问层 (Data)
- 封装数据库操作
- 提供CRUD接口
- 处理数据映射
- 管理数据库连接

#### 基础设施层 (Infrastructure)
- 提供通用技术服务
- 加密解密功能
- 配置管理
- 工具类

### 3.2 依赖规则

```
表示层 ──依赖──▶ 业务逻辑层
业务逻辑层 ──依赖──▶ 数据访问层
数据访问层 ──依赖──▶ 基础设施层

禁止反向依赖！
```

## 6. 安全架构

### 6.1 加密层次

```
┌─────────────────────────────────────────────────────────────────┐
│                        安全层次架构                             │
└─────────────────────────────────────────────────────────────────┘

  应用层
  ┌─────────────────────────────────────────────────────────────┐
  │  主密码验证                                                  │
  │  • Argon2id哈希（内存密集型，抗GPU攻击）                     │
  │  • 随机盐值（每个用户唯一）                                  │
  │  • 可配置参数（内存、迭代次数、并行度）                      │
  └─────────────────────────────────────────────────────────────┘
                               │
                               ▼
  传输层
  ┌─────────────────────────────────────────────────────────────┐
  │  密钥派生                                                    │
  │  • 从主密码派生加密密钥                                      │
  │  • 使用Argon2id算法                                          │
  │  • 32字节（256位）密钥长度                                   │
  └─────────────────────────────────────────────────────────────┘
                               │
                               ▼
  存储层
  ┌─────────────────────────────────────────────────────────────┐
  │  数据加密                                                    │
  │  • AES-GCM-256加密算法                                       │
  │  • 随机IV（每次加密唯一）                                    │
  │  • 认证加密（防篡改）                                        │
  └─────────────────────────────────────────────────────────────┘
```

### 6.2 密码学参数

| 算法 | 参数 | 说明 |
|------|------|------|
| Argon2id | 内存：64MB，迭代：3，并行度：1 | 抗GPU/ASIC攻击 |
| AES-GCM | 密钥：256位，IV：96位，Tag：128位 | 认证加密 |
| 盐值 | 128位随机值 | 每个用户唯一 |
| IV | 96位随机值 | 每次加密唯一 |

### 6.3 安全措施

#### 内存安全
- 使用`char[]`而非`String`存储密码
- 及时清除敏感数据
- 避免内存转储泄露

#### 剪贴板安全
- 自动清除剪贴板（可配置时间）
- 监控剪贴板内容变化
- 安全清除机制

#### 会话安全
- 超时自动锁定
- 活动监控
- 敏感数据清除

## 8. 关键设计决策

### 8.1 架构模式选择

**决策**：分层架构

**理由**：
- 职责分离清晰
- 便于测试和维护
- 适合中等规模应用
- 支持团队协作开发

**替代方案**：
- MVC模式：更适合Web应用
- 微服务架构：过于复杂

### 8.2 数据库选择

**决策**：SQLite

**理由**：
- 嵌入式数据库，无需安装服务器
- 单文件存储，便于备份和迁移
- 支持SQL标准
- 性能满足需求

**替代方案**：
- H2：类似，但SQLite更成熟
- PostgreSQL：过于复杂

### 8.3 加密算法选择

**决策**：Argon2id + AES-GCM-256

**理由**：
- Argon2id：抗GPU/ASIC攻击，可配置参数
- AES-GCM-256：认证加密，防篡改
- 组合使用：主密码哈希 + 数据加密

**替代方案**：
- bcrypt：不如Argon2id安全
- AES-CBC：不提供认证

### 8.4 GUI框架选择

**决策**：Swing

**理由**：
- Java标准库，无需额外依赖
- 学习曲线平缓
- IDEA支持良好
- 功能足够

**替代方案**：
- JavaFX：更现代，但需要额外依赖
- SWT：平台相关性强

## 10. 性能考虑

### 10.1 性能瓶颈

- **加密操作**：Argon2id故意设计为慢速
- **数据库查询**：需要优化索引
- **UI渲染**：大量数据时的性能

### 10.2 优化策略

- **缓存**：会话数据、配置数据
- **异步操作**：加密、数据库操作
- **分页**：大量数据的展示
- **索引优化**：数据库查询优化

### 10.3 资源管理

- **内存**：及时释放敏感数据
- **连接池**：数据库连接管理
- **线程管理**：后台任务处理

## 12. 风险评估

### 12.1 安全风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 主密码泄露 | 高 | 强密码策略、超时锁定 |
| 数据库泄露 | 高 | 强加密、文件权限 |
| 内存转储 | 中 | 及时清除敏感数据 |
| 剪贴板泄露 | 中 | 自动清除、监控 |

### 12.2 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 加密算法过时 | 中 | 模块化设计，易于替换 |
| 依赖库漏洞 | 中 | 定期更新依赖 |
| 数据库损坏 | 高 | 定期备份、事务保护 |

## 13. 总结

密码管理器采用分层架构，确保了：
- **安全性**：强加密算法保护敏感数据
- **可维护性**：清晰的代码结构和模块化设计
- **可扩展性**：易于添加新功能
- **可用性**：直观的图形用户界面

架构设计遵循了高内聚、低耦合的原则，为系统的长期维护和扩展奠定了良好基础。
